# General Product Setup automation coverage

Source: AIO Tests project `FS`, folder `228402` (General Product Setup), 102 cases. The source set contains copied cases; each case has its own spec file and retains its AIO key/title.

All source preconditions: user is logged in, Loan Origination is selected, and Loan Product Configuration is open. Tests navigate directly to the verified `/loan-product-config/add` route using authenticated browser storage state.

## Environment and execution

1. Create a local authenticated state without putting credentials in the repository:
   ```powershell
   New-Item -ItemType Directory -Force .auth
   npx playwright codegen --save-storage=.auth/user.json https://frontend.aws-stage.flowsky.co/loan-product-config/add
   ```
   Sign in manually in the opened browser, then close it to save the state file. `.auth/` is ignored by git.
2. Set variables and run discovery/execution from the workspace root:
   ```powershell
   $env:LOAN_PRODUCT_APP_URL = 'https://frontend.aws-stage.flowsky.co'
   $env:PLAYWRIGHT_STORAGE_STATE = '.auth/user.json'
   npx playwright test tests/ui/loan-product-configuration/01-General-Information/add --project=chromium --list
   npx playwright test tests/ui/loan-product-configuration/01-General-Information/add --project=chromium --reporter=list
   ```
Tests skip explicitly when the app URL or authenticated storage state is not supplied. Clipboard cases run in Chromium only.

## Verified UI constraints and discrepancies

- Product ID input limit is 20 characters; Product Description limit is 1,000 characters and excess text is trimmed.
- Product Type currently offers Business Loan, Car Loan, Education Loan, Equipment Loan, Home Loan, and Personal. Currency currently offers EGP, USD, and EUR. Status offers Active and Inactive and defaults to Active.
- AIO expects Product ID placeholder `e.g., MF001, GL001`, but the inspected app displays `e.g., MF-001, GL-001`; AIO expects a default Product Type of Business Loan, but the inspected app displays `Select a product type`. Assertions preserve the AIO expectations.
- Target Segment is not present on the inspected General Information form. Its label assertion is retained; option/selection/mobile cases are partial because the UI control is missing.
- The product-name input has no maxlength attribute in the inspected build. Validation on blur for invalid name/code values was not observed.
- No test submits or persists a new product. Duplicate and conditional refresh cases are blocked until deterministic setup and safe cleanup are available.
