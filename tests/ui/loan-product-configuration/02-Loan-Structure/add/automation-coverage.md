Source workbook: `Loan_Structure_AIO_Import_14Oct20263.xlsx`, worksheet `AIO Import - All Cases`. The project catalog retains 69 cases after removing two API/security cases from the original 71-case set.

The retained cases have 53 populated AIO `Key` values and 16 blank keys. For blank-key rows, the title-embedded `LS-NEW-*` identifier is preserved as a provisional case identifier; it is not represented as an AIO key. There is no dedicated Priority, Folder, or Test Suite column; priority and requirements appear only in Description where supplied.

## Source requirements and analysis

- Preconditions require an authenticated user permitted to edit Loan Product Configuration and a draft product whose General Information step is complete.
- The verified test flow creates a unique draft through Step 1 and enters Step 2. No safe delete operation was verified; executions can leave draft products behind.
- Existing staging evidence supports the baseline values, section controls, amount/tenure validation, switch visibility, saved state, and the tested UI controls.
- Do not infer business rules where the workbook explicitly awaits confirmation (Q-01 through Q-24). Those cases are partial or blocked with the specific dependency noted below.
- Purchase/QR, loan activation, submitted-product approval, and audit-history scenarios require unavailable fixtures or interfaces and are blocked. API/security test cases were removed from this suite.

$env:LOAN_PRODUCT_APP_URL = 'https://frontend.aws-stage.flowsky.co'

## Validation and staging execution

- Playwright discovery found 71 tests in 71 files before the API/security cases were removed.
- The authorized full Chromium staging run completed with 39 passed, 8 failed, and 24 skipped. The 24 skips are blocked scenarios.
- Six failures from that run were automation issues and have since passed targeted validation: five passed in the six-case rerun; FS-TC-1232 passed in a subsequent focused rerun after its decimal rejection assertions were corrected.
- FS-TC-190 and FS-TC-208 remain application findings: staging silently changed a 15-digit amount from `999999999999999` to `999999999`, and changed Max Months from `1000` to `100`. Their exact-value assertions remain in place.
- Strict TypeScript checking passed for the changed shared helper and FS-TC-1232 spec using a transient TypeScript compiler; the project does not declare TypeScript as a dependency. The full 71-file strict check had passed before this final adjustment.
- Staging execution creates persistent draft products; no verified cleanup operation is available.
